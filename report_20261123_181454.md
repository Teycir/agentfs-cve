## 1. Executive Summary

### 1.1 Background

Objective was to find a CVE-worthy vulnerability in `agentfs` 0.6.4 with emphasis on integrity/privilege flaws over generic reads. The security boundary selected for audit was the filesystem exposure surface: FUSE sandbox, ptrace sandbox, direct AgentFS, and `agentfs serve nfs`. The engagement used source review followed by live end-to-end proof on loopback.

### 1.2 Overall posture

The NFS serving path is the weak boundary. `agentfs serve nfs` in overlay mode wraps a `HostFS` base directory in `OverlayFS` and exposes it through a minimal ONC RPC/NFSv3 server. The server correctly enforces coarse operation permissions, but it does not enforce the NFS LOOKUP contract that `filename3` is a single path component. Raw RPC clients can supply `/`, `..`, or absolute pathnames, and the request reaches `HostFS::lookup`/`openat` without confinement checks. This produces arbitrary host file read outside the configured export base.

The FUSE path was not exploitable by the same mechanism because the kernel resolves path components before LOOKUP. The ptrace sandbox was not exploitable through the audited path because it mounts `SqliteVfs` only; the `BindVfs` traversal candidate is dead code in v0.6.4. Overlay write paths redirect mutations to the SQLite delta layer, so the confirmed impact is disclosure, not host file modification.

### 1.3 Risk profile

| Severity | Count |
|---|---:|
| Critical | 0 |
| High | 0 |
| Medium | 1 |
| Low | 0 |
| Informational | 3 secondary observations |

Primary risk: local or network file disclosure when `agentfs serve nfs` is reachable. Default bind is `127.0.0.1`, which limits remote exposure but does not isolate local users; `--bind 0.0.0.0` or a routed address makes the same primitive remote.

### 1.4 Recommendation summary

1. **AFS-NFS-01 (Medium):** Validate NFS LOOKUP names as single path components and enforce root containment in `HostFS` before dispatching to `openat`.
2. Do not treat AUTH_UNIX uid/gid as authentication on an unauthenticated RPC service; document the real boundary.
3. Avoid copy-up on read-only opens so host file contents are not persisted into the SQLite delta.
4. Keep `serve nfs` loopback-only unless a fix and real auth are in place.

## 4. Findings Detail

### 4.1 AFS-NFS-01 — NFS LOOKUP accepts absolute/traversal filenames and reads host files outside the export base

**Severity:** Medium  
**CVSS 3.1:** 5.5 — `CVSS:3.1/AV:L/AC:L/PR:L/UI:N/S:U/C:H/I:N/A:N`  
**Alternate:** 7.5 — `CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:N/A:N` when bound off-loopback  
**CWE:** CWE-22, CWE-73  
**Affected area:** `agentfs serve nfs` / `agentfs nfs` overlay mode (`HostFS` base + `OverlayFS` delta)  
**Difficulty to exploit:** Low — raw ONC RPC client; no kernel NFS client required  
**Authentication required:** None; RPC accepts `AUTH_NULL` and `AUTH_UNIX`  
**User interaction required:** None  
**Verified at (UTC):** 2026-11-23T18:05:28Z–2026-11-23T18:14:02Z

#### Issue description

The NFSv3 LOOKUP procedure deserializes `diropargs3` and calls `context.vfs.lookup(dirid, &dirops.name)` after an execute-permission check on the parent directory. `AgentNFS::lookup` converts the opaque filename to UTF-8 and forwards it unchanged. `OverlayFS::lookup` uses the name to build bookkeeping paths and calls `self.base.lookup(base_parent_ino, name)`. `HostFS::lookup` executes:

```rust
libc::openat(parent_fd, c_name.as_ptr(), libc::O_PATH | libc::O_NOFOLLOW)
```

with no rejection of `/`, `..`, or absolute paths. `O_NOFOLLOW` protects only the final component; an absolute pathname causes the kernel to ignore `parent_fd` entirely.

Verified behaviors on the live server:

- `LOOKUP "../outside_secret.txt"` from export root read `/tmp/opencode/agentfs-lab/outside_secret.txt` (one level above base).
- `LOOKUP "../../../../etc/passwd"` read `/etc/passwd`.
- `LOOKUP "/etc/passwd"` read `/etc/passwd` directly.
- `LOOKUP "../secret_600.txt"` + `READ` returned a mode-600 file owned by the server user when the RPC credential claimed `AUTH_UNIX uid=0`; the same READ with `uid=65534` was denied `NFS3ERR_ACCES` (status 13).

#### Attack scenario

1. Operator initializes an overlay AgentFS for a project and runs `agentfs serve nfs` so another process/host can mount it.
2. Attacker speaks ONC RPC directly to the NFS port. The Linux kernel NFS client is not suitable because it normalizes paths client-side; raw RPC can send arbitrary `filename3` bytes.
3. Attacker MNTs `/`, then LOOKUPs `/etc/passwd`, `../../../../home/<user>/.ssh/id_rsa`, or another path readable by the `agentfs` process, then READs it.
4. Because `OverlayFS::open` copy-ups base files even for `O_RDONLY`, the read also copies the host file into the AgentFS SQLite delta, persisting contents in the agent database and creating memory/disk pressure for large files.

#### Impact

- **Confidentiality:** arbitrary read of host files accessible to the `agentfs` process, outside the exported base. Default loopback still crosses the local-user boundary because loopback is reachable by other local users and AUTH_UNIX credentials are spoofable; off-loopback binds expose the primitive remotely.
- **Persistence/secondary effect:** `OverlayFS::open` performs copy-up for base files even for `O_RDONLY`, so traversed reads copy host file contents into the AgentFS SQLite delta. This can persist secrets in the agent DB and turn a small READ into a full-file copy (memory/disk pressure for large files). Not separately exploited for DoS under the non-destructive constraint.
- **Integrity/availability:** no host file write/delete was demonstrated; overlay mutations target the SQLite delta. Do not claim host modification without a separate primitive.
- **Affected demographic:** developers, researchers, and CI jobs that run `agentfs serve nfs` to export an overlay AgentFS on a shared host, container, or VM host; also relevant where AgentFS is used as the filesystem layer for coding agents and the NFS endpoint is reachable by less-trusted processes.

#### Recommended fix

1. Validate NFSv3 `filename3` in `AgentNFS`/`nfsproc3_*` before dispatch: reject empty names, `/`, `\`, NUL, names containing `/` or `..` components, and names longer than `NAME_MAX`. Treat LOOKUP names as single path components only.
2. Defense in depth in `HostFS`: resolve each lookup with `openat` per component and reject `..`/absolute paths, or verify the resulting path remains under the configured root (`O_PATH` + `openat2(RESOLVE_BENEATH|RESOLVE_NO_MAGICLINKS)` where available).
3. Do not trust AUTH_UNIX uid/gid for authorization decisions on a server with no authentication; at minimum document that NFS permission checks are advisory and the OS process credentials are the real boundary.
4. Consider copy-up-on-read policy: `OverlayFS::open` currently copies base files to delta even for `O_RDONLY`; reads could use the base fd directly to avoid persisting host file contents and full-file memory copies.

### 4.2 OBS-01 — MCP `--tools` filter does not re-check `is_tool_enabled` in `tools/call`

**Severity:** Informational  
**Status:** Confirmed by source; not exploited end-to-end  
**Verified at (UTC):** source review during engagement (2026-11-23)

`cli/src/cmd/mcp_server.rs` filters `tools/list` output when `--tools` is provided, but `handle_tools_call` does not appear to re-check `is_tool_enabled` before dispatch. A client can therefore call tools that were hidden from the list (e.g. `write_file`) if it knows the tool name. Impact is limited to the AgentFS delta/SQLite FS exposed by that MCP server, not the host filesystem.

### 4.3 OBS-02 — `HostFS` mutating ops exist but are not reachable for host paths through tested overlay NFS path

**Severity:** Informational  
**Status:** Confirmed by source  
**Verified at (UTC):** source review during engagement (2026-11-23)

`HostFS` implements `mkdir`, `create_file`, `unlinkat`, `rename`, `symlink`, and permission ops with raw names/paths. However `OverlayFS` routes mutations to the SQLite delta layer (`fs_whiteout`, `fs_overlay_config`, delta inodes), and `AgentFS::normalize_path` clamps `..` at the delta root. No host write primitive was confirmed through `serve nfs` overlay mode.

### 4.4 OBS-03 — Packet capture unavailable; record-level captures used

**Severity:** Informational  
**Status:** Environment limitation documented

- **SQL injection:** `sdk/rust/src/kvstore.rs` and `sdk/rust/src/toolcalls.rs` reviewed paths use parameterized queries.
- **Host write via NFS overlay:** overlay mutations are redirected to SQLite delta; no host write primitive confirmed.
